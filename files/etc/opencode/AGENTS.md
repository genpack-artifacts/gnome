# このシステムについて (genpack で生成された不変イメージ)

このマシンは **genpack** でビルドされた Gentoo Linux ベースの不変 (immutable) システムイメージ上で
動作しています。通常の Linux ディストリビューションをインストールした環境とは前提が異なるため、
作業前に以下を把握してください。

## ルートファイルシステムは読み取り専用 + overlay

- `/` は overlayfs です。lower は読み取り専用の SquashFS (`/run/initramfs/ro`)、
  upper はデータパーティション (Btrfs) または tmpfs です。
- **データパーティションを持たない構成 (トランジェントモード) では、実行中のファイル変更は
  再起動ですべて消えます。** 永続する変更のつもりで書き込む前に、どちらの構成かを確認してください
  (`grep ' / ' /proc/mounts` の `upperdir=` を見る)。

## 実行時にパッケージは入れられない

- 実行環境に Portage (`emerge`) はありません。他のパッケージマネージャもありません。
- 必要なパッケージがある場合、その場で入れようとせず、**アーティファクト定義
  (`genpack.json5` の `packages`) に追加してイメージを再ビルドする必要がある**ことを
  ユーザーに伝えてください。

## 設定変更をどこに書くかは、勝手に決めずユーザーに確認する

`/etc` 以下の変更をどう扱うかは**構成と運用方針によって変わります**。決めつけないでください。

- **データパーティションのある構成**: `/etc` への変更は overlayfs の upper 層に残り、
  再起動後も保持されます。この構成では、運用上の設定を実機の `/etc` に直接書くのは
  正当な選択肢です。
- **データパーティションのない構成 (トランジェントモード)**: `/etc` への変更は再起動で消えます。
  恒久化したいなら、アーティファクト定義の `files/etc/...` に入れてイメージを再ビルドする
  必要があります。

どちらの構成であっても、恒久的な設定変更を行う前に

1. 上記のとおり `/` の upper 層がどちらかを確認し、
2. **「実機の `/etc` に直接書くか、アーティファクト定義に入れて再ビルドするか」を
   ユーザーに確認してください。**

データパーティションがある構成でも、構成ドリフトを避けるためアーティファクト側に
寄せる運用をしていることがあります。逆に、その場で直したいだけのこともあります。
判断はユーザーのものです。

## このイメージの素性を確認する

`/.genpack/` にビルド時のメタデータがあります。問題の切り分けでは、まずここを見てください。

| ファイル | 内容 |
|---|---|
| `/.genpack/artifact` | アーティファクト名 |
| `/.genpack/variant` | バリアント名 |
| `/.genpack/profile` | ビルドプロファイル |
| `/.genpack/arch` | アーキテクチャ |
| `/.genpack/packages` | インストール済みパッケージ一覧 (USE フラグ・説明つき) |
| `/.genpack/timestamp.commit` | ビルドに使った Portage ツリーのコミット |

genpack のバージョンによっては他のファイルもあるので `ls /.genpack/` も確認してください。
「いつビルドされたイメージか」を稼働時刻や `/etc` のタイムスタンプから推測しないこと。

## 起動時の構成は system.ini

- 起動のたびに `genpack-init` が `system.ini` (ブートパーティションまたはデータパーティション上)
  を読んでシステムを構成します。ホスト名・ネットワーク・ユーザーなどの構成はここに集約されており、
  `/etc` 以下に散在させない設計です。
- したがって「次回起動時にも効く構成」を入れたい場合の置き場所は `system.ini` であって
  `/etc` ではありません。
